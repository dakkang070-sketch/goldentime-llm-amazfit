# 생체 데이터 누락 부분 개발 계획 (Backend Only - UI 변경 없음)

사용자님께서 요청하신 대로, 현재 시스템에 **누락된 생체 데이터**를 **내부 시스템에만** 완전히 구현하고, **UI는 절대로 변경하지 않습니다**.

---

## 1. 개발 목표 (Development Objectives)

현재 **심박수, 스트레스, 자이로스코프**는 완전히 구현되어 있으나, **혈압, 혈당, SpO2, 체온**은 **DB 저장 없이** 또는 **Mock 데이터**로만 처리되고 있습니다. 이를 실제 데이터 기반으로 전환합니다.

---

## 2. 누락된 데이터 구현 범위 (Missing Data Implementation Scope)

### A. 데이터베이스 스키마 확장 (Database Schema Extension)
*   **파일**: `backend/models/BiometricData.js`
*   **추가 필드**:
    *   `bloodPressure`: `{ systolic: Number, diastolic: Number }`
    *   `bloodGlucose`: `Number` (mg/dL)
    *   `spO2`: `Number` (%)
    *   `bodyTemperature`: `Number` (°C)

### B. 실시간 분석 엔진 확장 (Real-time Analysis Engine)
*   **파일**: `backend/services/realtimeBiosignalEngine.js`
*   **추가 로직**:
    *   **혈압 분석**: 수축기/이완기 기준으로 **고혈압(≥140/90)**, **저혈압(≤90/60)** 감지
    *   **혈당 분석**: 공복 기준 **고혈당(≥126 mg/dL)**, **저혈당(≤70 mg/dL)** 감지
    *   **체온 분석**: **고열(≥38°C)**, **저체온(≤35°C)** 감지
    *   **SpO2 분석**: 기존 **저산소증(<90%)** 로직을 실제 데이터 기반으로 전환

### C. AI 추론 엔진 확장 (AI Inference Engine)
*   **파일**: `backend/services/ollamaService.js`
*   **추가 컨텍스트**: 프롬프트에 혈압, 혈당, 체온, SpO2 데이터를 포함하여 종합적인 건강 상태 판단

### D. 데이터 수집 API 확장 (Data Collection API)
*   **파일**: `backend/routes/realtimeBiosignal.js`
*   **추가 엔드포인트**:
    *   `POST /api/realtime-biosignal/blood-pressure`
    *   `POST /api/realtime-biosignal/blood-glucose`
    *   `POST /api/realtime-biosignal/temperature`
    *   `POST /api/realtime-biosignal/spo2`

---

## 3. 개발 제약 조건 (Development Constraints)

1.  **UI 변경 금지**: 프론트엔드의 **모든 UI 컴포넌트, 레이아웃, 스타일**은 그대로 유지합니다.
2.  **Mock 데이터 제거**: 기존에 랜덤 생성되던 혈압/혈당/체온/SpO2 데이터를 **실제 센서 데이터**로 대체합니다.
3.  **기존 API 호환성**: 기존 `/api/realtime-biosignal/data` 엔드포인트는 **하위 호환성**을 유지하며, 새로운 필드는 **옵션**으로 처리합니다.

---

## 4. 개발 단계 (Development Phases)

### Phase 1: 데이터베이스 스키마 확장 (1일)
*   `BiometricData` 모델에 새로운 필드 추가
*   마이그레이션 스크립트 작성 (기존 데이터 보존)

### Phase 2: 실시간 분석 엔진 확장 (2일)
*   혈압/혈당/체온/SpO2 분석 로직 구현
*   임계치 기반 경고 시스템 통합

### Phase 3: AI 추론 엔진 확장 (1일)
*   OllamaService 프롬프트 템플릿 업데이트
*   종합 건강 지수 계산 로직 추가

### Phase 4: API 확장 및 통합 테스트 (1일)
*   신규 엔드포인트 구현
*   기존 시스템과의 통합 테스트

---

## 5. 기대 효과 (Expected Outcomes)

*   **데이터 무결성**: 모든 생체 데이터가 **영구 저장**되어 이력 추적 가능
*   **정확도 향상**: Mock 데이터 대신 **실제 센서 데이터** 기반 분석
*   **AI 판단 개선**: 더 많은 건강 지표를 종합하여 **정확한 응급 상황 판단**
*   **확장성**: 향후 **새로운 생체 지표** 추가가 용이한 구조

---

**⚠️ 중요**: 본 계획은 **UI를 전혀 건드리지 않으며**, **백엔드 시스템만** 확장하는 것을 원칙으로 합니다.
