# 골든타임 LLM 시스템 시나리오 분석

## 1. 시스템 개요

응급환자의 골든타임을 지키기 위한 실시간 생체 데이터 모니터링 및 자동 응급 구조 시스템

## 2. 주요 구성 요소

### 2.1 사용자 앱 (미니앱)
- **회원가입**: 본인인증 → 자동 등록(이름, 전화번호) + 수동 입력
- **초기 동기화**: Amazfit Watch와 2분간 기초 생체 데이터 수집
- **실시간 모니터링**: 1분 단위 생체 데이터 수집
- **입원/퇴원 모드**: 병원 위치 기반 자동 감지 및 수동 관리

### 2.2 LLM 분석 시스템
- **로컬 설치**: Llama 3.1 8B Q4 + Ollama
- **분석 기능**:
  - 기초선 기반 생체 리듬 분석
  - 패턴 인식 및 이상 징후 감지
  - 5단계 응급도 판정
  - 응급구조사 및 병원 자동 매칭
- **의료 분석 제한**: 의학적 분석 50% 수준 (의료기기 인증 회피)

### 2.3 관제센터
- **실시간 모니터링**: OpenStreetMap 기반 지도 표시
- **관제사 배정**: 회원별 관제사 자동 배정
- **수동 처리**: 시스템 오류 시 수동 매칭
- **상태 표시**: 환자, 응급구조사, 병원 위치 및 상태 표시

### 2.4 응급구조사 앱
- **매칭 수신**: 근거리 응급 상황 수신
- **승인 처리**: 업무 가능 상태일 때만 승인
- **이송 관리**: 환자 이송 및 상태 업데이트

## 3. 데이터 흐름

### 3.1 정상 상태
```
Amazfit Watch → Zepp Cloud API → 서버 → LLM 분석 → 정상 판정
```

### 3.2 응급 상황 감지
```
Amazfit Watch → Zepp Cloud API → 서버 → LLM 분석 → 이상 징후 감지
→ 5단계 응급도 판정 → 응급구조사 매칭 → 병원 매칭
→ 관제센터 알림 → 응급구조사 앱 알림
```

### 3.3 이송 프로세스
```
응급구조사 승인 → 환자 위치로 이동 → 도착 확인
→ 이송 준비 → 병원으로 이송 → 병원 도착 → 의사 인계 → 종료
```

## 4. 주요 프로세스

### 4.1 회원가입 프로세스
1. 본인인증 (미구현, 추후 연동)
2. 기본 정보 입력
3. 의료 히스토리 입력
4. 동의 항목 확인
5. Amazfit Watch 초기 동기화 (2분)
6. 기초 생체 데이터 수집 및 저장

### 4.2 실시간 모니터링 프로세스
1. Amazfit Watch에서 1분 단위 데이터 수집
2. Zepp Cloud API를 통해 서버로 전송
3. LLM 분석 엔진에서 실시간 분석
4. 이상 징후 감지 시 응급 프로세스 시작

### 4.3 응급 상황 대응 프로세스
1. **감지**: LLM이 이상 징후 감지
2. **판정**: 5단계 응급도 판정
3. **매칭**: 
   - 응급구조사 자동 매칭 (거리, 상태 체크)
   - 병원 자동 매칭 (거리, 이송가능 여부)
4. **알림**: 관제센터, 응급구조사 앱에 알림
5. **수동 처리**: 매칭 실패 시 관제사가 수동 처리

### 4.4 이송 프로세스
1. 응급구조사 승인
2. 환자 위치로 이동 (GPS 추적, 경로 표시)
3. 도착 확인 (앱 버튼 클릭)
4. 응급처리 및 이송 준비
5. 이송 버튼 클릭 → 병원으로 이동
6. 병원 도착 → 의사 인계
7. 이송 완료 처리 → 상황 종료

### 4.5 입원 모드 프로세스
1. 병원 위치에서 일정 시간 체류 감지
2. 앱에서 입원 확인 요청
3. 사용자가 입원 모드 활성화
4. 생체 데이터 모니터링 지속 (응급 구조 비활성화)
5. 퇴원 시 수동으로 퇴원 모드 전환

## 5. 기술 요구사항

### 5.1 외부 API
- **Amazfit Zepp API**: https://docs.zepp.com/docs/reference/app-json/
- **국립중앙의료원 API**: 병원 정보 조회
- **SMS API**: 보호자 알림 (미신청 상태)

### 5.2 데이터베이스
- **MongoDB**: 모든 데이터 저장
- **컬렉션**:
  - users (회원 정보)
  - biometric_data (생체 데이터)
  - emergency_cases (응급 상황)
  - paramedics (응급구조사)
  - hospitals (병원 정보)
  - controllers (관제사)
  - assignments (배정 정보)

### 5.3 LLM 설정
- **모델**: Llama 3.1 8B Q4
- **플랫폼**: Ollama (로컬)
- **분석 항목**:
  - 심박수 패턴 분석
  - 가속도/움직임 분석
  - 스트레스 지수 분석
  - 위치 정보 기반 상황 분석

## 6. 응급도 5단계

1. **1단계 (정상)**: 생체 데이터 정상 범위
2. **2단계 (주의)**: 약간의 이상 징후, 지속 모니터링
3. **3단계 (경고)**: 명확한 이상 징후, 관제사 알림
4. **4단계 (위급)**: 심각한 이상, 응급구조사 출동 필요
5. **5단계 (응급)**: 생명 위험, 즉시 응급구조사 출동
