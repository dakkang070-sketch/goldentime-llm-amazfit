# 🕐 API 데이터 갱신 주기 현황 및 최적화 방안

## 📊 현재 설정된 주기들

### 🏥 **국립중앙의료원 API 데이터**
- **캐시 주기**: `5분` (300,000ms)
- **실시간 병상 정보**: 수동 요청 시에만 갱신
- **자동 동기화**: ❌ **미설정** (수동으로만 가능)

### 🤖 **시스템 모니터링 주기들**

#### 품질 관리 (QualityManagementService)
```javascript
// 실시간 품질 모니터링
'*/10 * * * *'  // 10분마다

// 일일 품질 리포트
'0 9 * * *'     // 매일 오전 9시

// 주간 품질 분석
'0 10 * * 1'    // 매주 월요일 오전 10시

// 개선 작업 처리
'0 * * * *'     // 매시간
```

#### 자동 학습 시스템 (AutoLearningService)
```javascript
// 배치 학습
'0 2 * * *'     // 매일 오전 2시

// 증분 학습 모니터링
'*/5 * * * *'   // 5분마다 새 데이터 확인
```

#### 실시간 추적 서비스 (RealtimeTrackingService)
```javascript
// 응급구조사 위치 업데이트
5초마다 (5,000ms)

// 이송 진행상황 업데이트
10초마다 (10,000ms)
```

#### 리소스 관리 (ResourceManagementService)
```javascript
// 리소스 상태 업데이트
1분마다 (60,000ms)

// 용량 모니터링
30초마다 (30,000ms)
```

#### 응급 워크플로우 (EmergencyWorkflowService)
```javascript
// 활성 워크플로우 상태 검사
'*/5 * * * *'   // 5분마다

// 성능 리포트 생성
'0 * * * *'     // 매시간
```

## ⚠️ **현재 문제점**

### 🔴 **국립중앙의료원 API 자동 갱신 미설정**
- **문제**: 병원 데이터가 5분 캐시 후 수동 요청시에만 갱신
- **영향**: 최신 병상 현황 반영 지연 가능성
- **위험도**: 높음 (응급상황에서 실시간성 중요)

## 🚀 **권장 개선 방안**

### 1️⃣ **실시간 병상 현황 자동 갱신**
```javascript
// 권장 주기: 1-3분마다
'*/2 * * * *'   // 2분마다 (권장)
'*/1 * * * *'   // 1분마다 (고부하)
'*/3 * * * *'   // 3분마다 (절약형)
```

### 2️⃣ **병원 기본정보 자동 동기화**
```javascript
// 권장 주기: 1일 1회
'0 1 * * *'     // 매일 오전 1시 (권장)
'0 */6 * * *'   // 6시간마다 (빈번형)
```

### 3️⃣ **응급도별 차등 갱신**
- **Level 4-5 (극응급)**: 30초마다
- **Level 3 (응급)**: 1분마다  
- **Level 1-2 (일반)**: 5분마다

## 📈 **API 호출량 최적화**

### 현재 예상 호출량
```
실시간 병상 API: 수동 호출만
병원 목록 API: 수동 호출만
총 일일 호출: 최소 (비효율적)
```

### 최적화 후 예상 호출량
```
실시간 병상 API: 720회/일 (2분마다)
병원 목록 API: 1회/일 (오전 1시)
총 일일 호출: 721회/일 (효율적)
```

## 🔧 **구현 우선순위**

1. **🔴 긴급**: 실시간 병상 현황 자동 갱신 (2분 주기)
2. **🟡 중요**: 병원 기본정보 일일 동기화
3. **🟢 개선**: 응급도별 차등 갱신 로직
