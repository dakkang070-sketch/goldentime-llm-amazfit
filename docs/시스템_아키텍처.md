## 데이터 흐름

### 1. 정상 모니터링 흐름
1. Amazfit Watch → 생체 데이터 수집 (1분 단위)
2. Zepp Cloud API → 데이터 전송
3. 백엔드 서버 → MongoDB 저장
4. LLM 분석 → 정상 판정
5. 관제센터 → 모니터링 표시

### 2. 응급 상황 감지 흐름
1. LLM 분석 → 이상 징후 감지
2. 응급도 5단계 판정
3. 응급구조사 자동 매칭
4. 병원 자동 매칭
5. 관제센터 알림
6. 응급구조사 앱 알림

### 3. 이송 프로세스 흐름
1. 응급구조사 승인
2. GPS 추적 시작
3. 환자 위치 도착
4. 이송 준비
5. 병원으로 이동
6. 병원 도착 및 인계
7. 상황 종료

## 주요 컴포넌트

### 백엔드 서버
- **기술**: Node.js + Express
- **기능**:
  - RESTful API 제공
  - 실시간 데이터 처리
  - WebSocket 통신 (Socket.io)
  - 스케줄링 작업 (node-cron)

### 데이터베이스
- **기술**: MongoDB
- **컬렉션**:
  - users: 회원 정보
  - biometric_data: 생체 데이터
  - emergency_cases: 응급 상황
  - paramedics: 응급구조사
  - hospitals: 병원 정보
  - controllers: 관제사

### LLM 분석 시스템
- **기술**: Ollama + Llama 3.1 8B Q4
- **기능**:
  - 기초선 기반 패턴 분석
  - 이상 징후 감지
  - 응급도 판정 (5단계)
  - 매칭 추천

### 관제센터
- **기술**: Frontend (추후 구현)
- **기능**:
  - OpenStreetMap 지도 표시
  - 실시간 모니터링
  - 수동 매칭 처리
  - 경로 표시

## 외부 API 연동

### Amazfit Zepp API
- **용도**: 생체 데이터 수집
- **주소**: https://docs.zepp.com/docs/reference/app-json/
- **데이터**: 심박수, 가속도, 스트레스, 위치

### 국립중앙의료원 API
- **용도**: 병원 정보 조회
- **데이터**: 병원 목록, 응급실 상태, 이송 가능 여부

### SMS API (미신청)
- **용도**: 보호자 알림
- **상태**: 추후 연동 예정

## 보안 고려사항

1. **인증**: JWT 기반 인증
2. **암호화**: 비밀번호 bcrypt 해싱
3. **개인정보**: 민감 정보 암호화 저장
4. **위치 정보**: 정밀도 제어 설정

## 성능 최적화

1. **인덱싱**: MongoDB 인덱스 최적화
2. **캐싱**: 자주 조회되는 데이터 캐싱
3. **배치 처리**: 생체 데이터 배치 저장
4. **실시간 처리**: WebSocket을 통한 실시간 업데이트
